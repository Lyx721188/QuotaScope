# Windows 本机模型速度统计

账户展开页的模型占比与 Token 来自用量账本；速度和首字等待来自独立的本机时序扫描。速度包括请求等待时间，至少三条可测量回复才显示；没有足够记录时保持未知。

时序扫描保留最近 24 小时的现有 mtime 筛选规则，最多遍历 64 层目录、10,000 个目录项及 1,024 个 JSONL 文件。单文件最多 8 MiB、单行最多 4 MiB、实际累计输入最多 64 MiB；每个文件最多 100,000 行，最后一次限额探测可能多读 1 字节。总模型数最多 1,024。这些是扫描上限，不是整个进程的内存限额。

子目录链接沿用 Rust 文件类型筛选，不递归进入。遍历、读取和解析检查取消。文件读取前后核对长度与时间；读取失败、行/字节/记录超限、损坏 JSON 或读取中变化时，排除该文件全部时序，保留其他完整文件的测量结果。损坏后可能缺少请求边界，不能仅保留看似有效的回复再推算速度。

遇到上述缺口，账户详情显示“部分本机时序记录无法读取；速度只覆盖可读取的回复。”该提示与“计数可能不完整”分别记录，不更改 Token 总量、模型占比或 API 价值估算。修改时间筛选也不能证明已覆盖所有请求，其他设备和已删除记录不在本机样本内。

合成回归覆盖三个可测量回复、旧文件、目录/文件上限、累计读取与超大行、损坏/过多行、取消与恢复。隔离账户 UI 另检查损坏提示、修复刷新及 Token 保持；不读取真实账户或凭据。

在 `windows/` 执行定向回归：`cargo test --workspace --lib model_details::tests --locked -j 1`。

本说明对应 main 的未发布改动；Windows 1.3.1 尚未包含此扫描上限与提示。
