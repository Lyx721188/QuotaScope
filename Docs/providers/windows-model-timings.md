# Windows 本机模型速度统计

账户展开页的模型占比与 Token 来自用量账本；速度和首字等待来自独立的本机时序扫描。速度包括请求等待时间，至少三条可测量回复才显示；没有足够记录时保持未知。

时序扫描保留最近 24 小时的现有 mtime 筛选规则；实际回复完成时间和首字事件还必须落在扫描开始时刻之前的 24 小时内，两端包含。文件 mtime 较新不能使未来或过旧的事件进入速度统计。最多遍历 64 层目录、10,000 个目录项及 1,024 个 JSONL 文件。单文件最多 8 MiB、单行最多 4 MiB、实际累计输入最多 64 MiB；每个文件最多 100,000 行，最后一次限额探测可能多读 1 字节。总模型数最多 1,024。这些是扫描上限，不是整个进程的内存限额。

子目录链接沿用 Rust 文件类型筛选，不递归进入。遍历、读取和解析检查取消。文件读取前后核对长度与时间；读取失败、行/字节/记录超限、损坏 JSON 或读取中变化时，排除该文件全部时序，保留其他完整文件的测量结果。损坏后可能缺少请求边界，不能仅保留看似有效的回复再推算速度。

时序输出计数只接受 `0..=1,000,000,000,000` 的 JSON 整数；此上限是工程读取限制，不表示服务商允许的 Token 数量。显式负数、浮点数、字符串、null、超限计数，或 Codex 累计输出倒退，均使该文件时序成为缺口；不把非法值钳制为有效测量，也不猜测重置前后的增量。跨文件聚合检查整数溢出与有限时间，失败时保留此前完整聚合并记录缺口。未来/过旧事件正常排除，单独出现不会触发缺口提示。

遇到上述缺口，账户详情显示“部分本机时序记录无法读取；速度只覆盖可读取的回复。”该提示与“计数可能不完整”分别记录，不更改 Token 总量、模型占比或 API 价值估算。修改时间筛选也不能证明已覆盖所有请求，其他设备和已删除记录不在本机样本内。

合成回归覆盖三个可测量回复、旧文件、目录/文件上限、累计读取与超大行、损坏/过多行、取消与恢复，并检查 24 小时边界、未来事件、非法/最大允许计数、累计倒退及聚合溢出。隔离账户 UI 另检查损坏提示、修复刷新、未来首字事件排除及 Token 保持；不读取真实账户或凭据。

在 `windows/` 执行定向回归：`cargo test --workspace --lib model_details::tests --locked -j 1`。

本说明对应未发布改动；Windows 1.3.1 尚未包含此扫描上限、有效性检查与提示。
