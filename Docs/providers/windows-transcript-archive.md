# Windows 转录计数存档

Token 页的 Claude Code / Codex 本机扫描只读取当前磁盘上的 JSONL。文件被客户端删除或轮转后，重新扫描无法再看到它，所以扫描时把每个文件的测量结果写入一份不可重建的存档；界面上的历史因此不随源文件消失。存档只保存 Token 计数，不保存对话正文、标题以外的用户文字或任何凭据。

## 文件与身份

存档位于 `%APPDATA%/QuotaScope/archive-ledger-<provider>-<root-hash>.json`，`format = 1`。按来源（Claude Code / Codex）和转录根目录分别隔离：根目录路径哈希进入文件名，文件内 `root` 再记录规范化路径，根目录不匹配的存档按不可读处理。条目键是文件的完整路径；路径必须位于该 `root` 之下，且不允许 `.` 或 `..` 组件。

存档不在 `statistics_cache.rs` 的可重建文件白名单内，缓存清理与预算淘汰不会删除它；清空统计缓存后，已删除文件的历史仍然保留。

## 一次读取就是一个观察

每个文件保存最后一次观察：十五分钟桶 → 模型 → 四类 Token 计数，以及该次读取是否 partial。

- **完整读取替换旧观察**，包括显式零值和修正后的计数。客户端修正累计值或删除后重建同路径文件时，界面跟随最新一次完整读取。
- **partial 读取不覆盖也不合并**已有观察。此前按字段取最大值会把两次不同读取的类别拼成一个任何一次读取都没有产生过的数字，因此改为：保留已存观察的原始数值，并把该条目标记为 partial，本次读取整体标记不完整。partial 只用于填补存档完全没有见过的路径。
- 重新出现但只读到一半的文件保留旧完整数值并显示不完整，直到有一次完整读取把它整体替换。

## 读取与写入的边界

`Archive::load` 在语法检查之外拒绝以下内容，并把原文件视为不可读、保持不动：

- 非 `format = 1`、`root` 与调用方不一致、文件数超过 50,000；
- 任何 Token 类别为负、或超过 `MAX_STORED_COUNTER`（`1_000_000_000_000`，与两个读取器的单文件分类上限一致）；
- 槽位键不是本机格式化器写出的真实本地十五分钟（例如非补零或无效日期）；
- 条目键为空、位于根目录之外或包含父目录组件。

单个存档上限 64 MiB。写入经过同目录临时文件、`sync_all` 和 rename；取消会删除临时文件并保留旧存档；目标或临时路径不是常规文件时拒绝写入，已存历史不被覆盖。读取损坏、超限、未来 format 或数值异常的存档只把本次读取标为 partial，不写入空数据。

## 上限语义

`MAX_FILES = 50_000` 与 `MAX_STORED_COUNTER = 1e12` 共同保证任何合法存档的合计都落在 `i64` 内（50,000 × 1e12 × 4 < `i64::MAX`），因此 `TokenTally::total()` 的饱和加法在实际数据上不会触发，`transcript_archive` 的边界测试固定这一关系。提高任一项都是存档格式决策。

存档已满时：

- 已存文件（包括已删除文件）的历史原样保留，界面不回退到只显示当前文件；
- 无法接纳的新文件在本次读取中仍然计入显示，并整体标记为不完整；它们不会被写入存档。

## 当前范围与未完成项

- 只有 Claude Code / Codex 的原生 JSONL 扫描接入存档。其他来源仍按各自规则重读当前文件，删除后的保留尚未支持；新增来源前必须有稳定的文件身份与明确的覆盖语义。
- 没有跨文件回复去重。Claude streaming 的同文件 reply 修正、Codex fork 重放、复制或改名文件都不具备上游 `TranscriptArchive` 的 claim 体系；复制文件会在存档中作为独立路径分别计数。
- 账号/额度的连接缓存与存档无关；存档不参与账户读取或网络请求。
