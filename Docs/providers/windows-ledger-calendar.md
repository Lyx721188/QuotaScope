# Windows 用量账本的日期范围

本机记录按本机时区聚合到日期和 15 分钟桶。账本保留每个实际有记录的日期、模型、Token、定价与未计价计数；不根据空白日期推测缺失用量。

空白日期只在最新记录之前最多 366 天内补齐，且不会延伸到最早记录之前。更早的长空档保存为稀疏日期，因此两条相隔数千年的有效时间记录不会生成数百万空白行。输出行数最多为实际记录日期数加 366；这不是整个进程的内存上限，也不限制实际记录的年份或删除旧计数。

“最近 N 天”的账本辅助方法按最新记录日期计算日历截止日，不按最近 N 行计算。今日查询直接查找今日日期，未来记录不会遮住今日数据。Token 页的今日、7/30/90 天和全部时间筛选沿用按日期筛选，统计截止到今天，未来日期不加入这些当前统计。

卡片图表使用固定的 30 个日历位置；Token 页缩略图按首尾日期跨度分成最多 40 个时间区间，空区间保留，不把旧空档压成连续活跃日期。空白日期的压缩不会把来源标记为“不完整”，因为它没有丢弃实际计数。读不到或无法确认计数的记录仍由各读取器单独标记。

定价在记录、模型、日期规划及输出过程中检查取消；取消不会返回半份账本。模型分项直接移入最终日期行，减少临时复制。

合成回归包括 1970/9999 年记录的计数与费用保留、短空档补零、稀疏历史的日历窗口、未来记录与今日查询、日期规划和输出中的取消，以及缩略图时间位置。隔离 Token UI 另检查跨年份导入、今日与全部时间切换及清除恢复。这些合成数据不代表真实账户验收。

本说明对应 main 的未发布改动；Windows 1.3.1 尚未包含此修复。
